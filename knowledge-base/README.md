# دانش‌نامه‌ی چت‌بات Nova (RAG)

این فولدر مجموعه‌ی اسناد NG AI Learning and Automation است که برای تغذیه‌ی چت‌بات **Nova** به‌سبک **RAG** (تولید مبتنی بر بازیابی) آماده شده است.

> همه‌ی محتوا فارسی و هماهنگ با لحن برند NG است. نام فایل‌ها و فولدرها انگلیسی است تا با ابزارهای پردازش بهتر کار کند.

## ساختار فولدرها

| فولدر | محتوا |
|-------|-------|
| `01-company/` | معرفی شرکت، حقایق کلیدی، بنیان‌گذار |
| `02-services/` | کاتالوگ خدمات، شرح خدمات، روش کار، قیمت‌گذاری |
| `03-process/` | فرایند همکاری و چک‌لیست شروع |
| `04-support/` | پرسش‌های متداول، پاسخ به نگرانی‌ها، تماس |
| `05-proof/` | مطالعات موردی و نظرات مشتریان |
| `06-content/` | مقالات بینش و واژه‌نامه |
| `07-policies/` | سیاست‌ها و بروشور شرکت |

## پوشش فرمت‌ها

| فرمت | نمونه فایل | کاربرد در RAG |
|------|-----------|----------------|
| Markdown (`.md`) | `company-profile.md`، مقالات | متن غنی و ساختاریافته؛ مناسب‌ترین برای chunking |
| JSON (`.json`) | `faq.json`، `services-catalog.json` | داده‌ی ساختاریافته‌ی پرسش/پاسخ و کاتالوگ |
| YAML (`.yaml`) | `company-facts.yaml` | حقایق کلیدی برای پاسخ‌های کوتاه و دقیق |
| CSV (`.csv`) | `pricing-packages.csv`، `glossary.csv` | داده‌ی جدولی (قیمت، واژه‌نامه) |
| TXT (`.txt`) | `contact-and-hours.txt` | متن ساده و سریع |
| HTML (`.html`) | `company-brochure.html` | سند صفحه‌بندی‌شده (منبع PDF) |

## فهرست اسناد
فایل [`manifest.json`](manifest.json) فهرست کامل تمام اسناد را با متادیتا (عنوان، مسیر، فرمت، موضوع، مخاطب) دارد. این فایل نقطه‌ی ورود مناسبی برای اسکریپت تزریق (ingestion) است.

## نکته‌ی مهم درباره‌ی داده‌ی این نسخه
- **اطلاعات واقعی** (نام شرکت، بنیان‌گذار، خدمات، ارزش‌ها، رنگ‌های برند، لینک تماس/رزرو) از پروژه‌ی وب‌سایت اصلی و برند گاید NG استخراج شده است.
- **قیمت‌ها، مطالعات موردی و نظرات مشتریان** هنوز در منابع موجود نبودند؛ این بخش‌ها با علامت `[TODO]` مشخص شده‌اند تا با داده‌ی واقعی تکمیل شوند. تا آن زمان، چت‌بات نباید این موارد را از خودش بسازد.

## مرحله‌ی بعد (خارج از محدوده‌ی این فولدر)
گام بعدی ساخت یک خط لوله است که این اسناد را می‌خواند، آن‌ها را به قطعه (chunk) می‌شکند، embedding می‌سازد و در یک پایگاه برداری (مثلاً `pgvector` روی همان Supabase پروژه) ذخیره می‌کند. اسکریپت `scripts/ingest-kb.mjs` نقطه‌ی شروع این کار است.
